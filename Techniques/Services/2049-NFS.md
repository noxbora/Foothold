# 2049 — NFS

A file server that hands out directories over the network and trusts the client to say who it is. There is no password: the client sends a numeric user id, and the server applies that user's permissions. Whoever controls the client controls the identity, which is what makes this service worth the visit.

## 1 — What is running, and what is exported

```bash
rpcinfo -p TARGET
```

- The reply lists every registered program with its version and port. It tells you which protocol versions are on offer, and that single fact changes everything below: version 3 lists its exports to anyone, version 4 does not.
- `111` is the portmapper itself. It is frequently open when `2049` is filtered, and it still answers, so a closed `2049` in your scan is not the end of the question.
- Note the highest version number beside the file-server entry before running anything else.

## 2 — Mounting it, and being the right person

```bash
sudo mount -t nfs -o ro,vers=3 TARGET:/srv/share /mnt/target
```

```bash
ls -lan /mnt/target
```

- Mount read-only first. A writable mount invites a mistake on someone else's filesystem, and nothing in this section needs write access.
- `-o vers=3` is worth stating explicitly. A client that negotiates version 4 against an export written for version 3 fails with a message about the path, which reads like the export name is wrong when it is not.
- `ls -lan` is the load-bearing command, and `n` is why: it prints numeric owner ids instead of translating them into your machine's names. Your `alice` and their `alice` are different people; the number is the only thing both sides agree on.
- A file you cannot read is owned by a numeric id you are not. Create a local user with that exact id, become them, and the server will hand the file over, because the id is the whole of the authentication.
