# 445 — SMB

Server Message Block: Windows file and printer sharing, and the protocol most lateral movement rides on. Reach for this note the moment 445 (or 139) shows up. It is worth the most of any port on a Windows box, because a share plus a credential is often the whole engagement.

## List the shares with no credential

**Why now** — nmap says 445 is open and you hold nothing. Before guessing a password, ask the cheapest question the protocol answers: does this host let a nameless session read the share list? A `null session` costs one command and sometimes hands you a readable share outright.

```bash
smbclient -L //<IP> -N
```

- `-L` → list the shares rather than connecting to one.
- `-N` → no password, the null session. Drop it and `smbclient` prompts for a password and your no-credential probe becomes a hung login instead of the answer you wanted.

**What you will see**

- **Found** — a table of share names with `Disk`/`IPC` types. A share with an unusual name (`backups`, `dev`, `web`, a username) is a lead; the ability to list *at all* over `-N` is a finding on its own.
- **Empty** — a share table containing only the stock names is still meaningful: it says the null session was accepted. That is different from the session being refused.
- **Error** — `NT_STATUS_ACCESS_DENIED` means anonymous listing is blocked and you need any credential. `NT_STATUS_CONNECTION_REFUSED` means nothing is on 445 despite the scan; try 139.
- **Noise** — `ADMIN$`, `C$`, `IPC$` and `print$` appear on nearly every Windows host. They are default administrative shares, not findings by themselves — see the next two sections for which of them matter.

**Then** — a listable non-default share goes to *Connect to a share*. `NT_STATUS_ACCESS_DENIED` goes to *Enumerate before authenticating* to squeeze the OS and user list out of what null access still allows, then to a credential hunt in [[Config-File-Looting]].

## Connect to a share

**Why now** — you have a share name worth reading, either from the null-session list or from a credential you just found. This opens it so you can walk the files.

```bash
smbclient //<IP>/<share> -N
```

- swap `-N` for `-U '<domain>\<user>%<pass>'` once you hold a credential. The inline `%pass` form skips the interactive prompt, which matters when you are scripting the same connection across several shares.

Inside the prompt, `get`, `put`, and `mget *` move files. To pull a whole tree at once:

```text
recurse ON
prompt OFF
mget *
```

- `recurse ON` → without it `mget *` takes only the current directory and a deep share comes back looking nearly empty.
- `prompt OFF` → without it every file waits for a `y`, which on a large share reads as a hang.

**What you will see**

- **Found** — a `smb: \>` prompt and a directory you can `ls`. Files with real names — `web.config`, `.kdbx`, a backup, a script — are the payoff.
- **Empty** — a share that connects but lists nothing may be genuinely empty, or you may lack read on its subdirectories while holding it on the root. `ls` a subdirectory to tell the two apart.
- **Error** — `NT_STATUS_ACCESS_DENIED` here, after a successful `-L`, means you can see the share exists but not read it: you need a *better* credential, not any credential. `NT_STATUS_BAD_NETWORK_NAME` means that share does not exist — you guessed or mistyped the name.
- **Noise** — an empty `IPC$` is normal; it is the inter-process channel, not a file share, and is not meant to hold anything.

**Then** — readable files go to [[Config-File-Looting]]. A **writable** directory goes to *When a share is writable*. `NT_STATUS_ACCESS_DENIED` sends you to hunt a stronger credential ([[Windows-Credential-Harvesting]]).

## Which of those shares you can actually read

**Why now** — the listing gave you names and said nothing about access. Connecting to each share in turn to find out is one session per share and a guess at the order to try them in; one command answers it for every share at once, and it answers the write question too.

```bash
smbmap -H <ip>
```

- no credential flags at all → a nameless session is this tool's default when no user is given, so the command above is the anonymous probe. Add `-u '<user>' -p '<password>'` (and `-d <domain>` for a domain account) and the same command becomes the fastest way to learn what a credential you just found is actually worth.
- the column that matters is permissions: `READ`, `READ, WRITE` or `NO ACCESS` per share. That is the difference between this and the share listing above, which proves a share exists and nothing more.
- `-r <share>` walks the contents of one share once you know it opens, and `--depth <n>` bounds how far down it goes. Start shallow: a share with a deep tree turns a two-second answer into a long one.

> [!important] The permissions column is a test the tool ran, not a field the server published
> It works out `WRITE` by creating a directory on the share and then removing it, falling back to creating and removing a file. So this command is not a read-only probe: on every share you can write to, it leaves a create and a delete behind in the file system and in whatever auditing is watching that share. Know that before you fire it at a production file server, and know it when you are asked afterwards what you touched.

**What you will see**

- **Found** — the share table with a permissions column beside it. A non-default share reading `READ` is where you go first; one reading `READ, WRITE` is a foothold and belongs in the writable section below.
- **Empty** — every row `NO ACCESS` while the plain listing worked is a real configuration, not a failure: this host lets a nameless session see the names of its shares and nothing inside them. You need any credential at all, and the note stops here until you have one.
- **Error** — a session error rather than a table means anonymous access is refused outright, the same wall `smbclient -L` hits. A connection error against a host whose 445 was open in the scan usually means you are pointing at the wrong address in a copied command.
- **Noise** — `READ` is measured at the share's root, and permissions are set per directory underneath it. A share you can list can still deny you one folder in, so the column is a shortlist rather than a verdict. `IPC$` answering at all says nothing about files; it is the channel, not a share.

**Then** — a readable share goes to *Connect to a share* above, a writable one to *When a share is writable* below, and a table of nothing but `NO ACCESS` sends you to *Enumerate before authenticating* to get what the nameless session will still give you.

## Reach the administrative shares

**Why now** — you hold a credential and want to know what it is worth. The hidden `$` shares are the test: reaching `C$` or `ADMIN$` means the account is a local administrator, which is the difference between a foothold and owning the box.

<!-- dup-ok -->
```bash
smbclient \\\\10.10.10.131\\ADMIN$ -U Administrator
```

- `\\\\` → a [[Security-Terms#^unc|UNC path]] with each backslash escaped for bash; four backslashes render as the two the client needs.
- `ADMIN$` → the hidden share mapped to `C:\Windows`. Writable `ADMIN$` means code execution via [[Security-Terms#^psexec|PsExec]] — that is the lateral-movement route, not just file access.
- `-U Administrator` → the account to authenticate as; add `%<pass>` or `-U '<domain>\<user>'` for a domain account.

**What you will see**

- **Found** — a prompt on `ADMIN$` or `C$`. That access **is** the finding: this credential is local admin here, so stop enumerating shares and move to execution.
- **Empty** — not applicable; you either reach the share or you are refused.
- **Error** — `NT_STATUS_ACCESS_DENIED` on `C$`/`ADMIN$` while ordinary shares open fine means the credential is valid but not administrative. That is a precise finding: you know exactly what privilege you are missing.
- **Noise** — none here; the `$` shares do not respond to null sessions, so anything that answers is a real credential result.

**Then** — administrative access goes to [[Active-Directory-Lateral-Movement]] for PsExec and to [[Windows-Credential-Harvesting]] to pull secrets off the box. A non-admin credential goes back to *Connect to a share* to see what it *can* read.

## Enumerate before authenticating

**Why now** — even when the share list is denied, the null session usually still answers questions about the host itself. The OS build feeds an exploit search and a user list feeds a password spray, and both come out of one sweep before you hold any credential.

```bash
nmap --script smb-enum-shares,smb-os-discovery,smb-security-mode -p445 <ip>
```

```bash
enum4linux-ng -A <ip> -oA results
```

- `smb-os-discovery` → OS build and hostname with no credential, straight into [[Public-Exploit-Workflow]] if the build is old.
- `-A` → every check the tool has, over a null session, in one sweep: users, groups, shares, the password policy, the identifier walk and the OS details. The user list it prints is the input to a spray, and the policy it prints is what tells you how fast you may run one.
- `-oA results` → writes the same findings out as structured files you can grep an hour later, one file per format. Give it a name with an extension already on it and you get `results.txt.json`, which is harmless and looks like a bug.
- the older `enum4linux` is still on most distributions and is a shell wrapper around the same underlying tools; the rewrite above adds the parsing. When a command in a write-up uses `-a` rather than `-A`, that is which one it means.

**What you will see**

- **Found** — from `smb-os-discovery`, an OS build string and domain name. From `enum4linux`, a block of `user:[name]` lines — write every one down.
- **Empty** — `enum4linux` returning no users is not proof there are none; a hardened host refuses [[Security-Terms#^rid|RID]] cycling over null sessions, so empty here means "not visible anonymously," not "none exist."
- **Error** — `NT_STATUS_ACCESS_DENIED` scattered through the `enum4linux` output is expected on a modern host and does not mean the tool failed; read past it for the sections that did return.
- **Noise** — `enum4linux` lists the built-in accounts (`Administrator`, `Guest`, `krbtgt`) on every host. The interesting names are the ones somebody created.

**Then** — a user list goes to a spray with a found or guessed password (the [[Custom-Wordlist-Attack-Chain]] builds the list). An old OS build goes to [[Public-Exploit-Workflow]]. `smb-security-mode` reporting message signing `disabled` or `not required` is worth recording separately — it is the precondition for an [[Security-Terms#^ntlm|NTLM]] relay, even though the relay itself is out of scope here. Still nothing usable sends you to [[Config-File-Looting]] on any other foothold to find a credential to bring back.

## When a share is writable

**Why now** — you found a directory you can write to. Beyond dropping a payload where a web server or a job will run it, SMB offers a trick no other file service does: a planted file that forces any user browsing the share to authenticate **to you**, handing over their NTLM hash.

**What you will see**

- **Found** — a shortcut file you drop with an icon path pointing at your own host (`\\<your-ip>\share\x`) makes Explorer fetch that icon over SMB the moment the folder is viewed, and your listener catches a `NetNTLMv2` hash for whoever looked. Which shortcut type still works is a patch-level question, and the file, the listener and the quoting that breaks the path are all in [[Authentication-Coercion]].
- **Empty** — nobody browsing the share means no hash arrives. This route needs a human (or a job) to open the directory; against an unvisited share it produces nothing.
- **Error** — `NT_STATUS_ACCESS_DENIED` on the upload means the write permission you saw was on the share, not on the directory inside it; prove it with a harmless file before planting anything. A file that uploads successfully and then disappears is antivirus on the server removing it, which tells you the share is watched and the drop was noticed.
- **Noise** — your own connection can trip the capture and log your own account. Filter the captured username against the users you already know are yours.

**Then** — planting the file is [[Authentication-Coercion]], and a captured `NetNTLMv2` hash goes from there to [[Hash-Cracking]] (mode 5600) — it is not usable for pass-the-hash, only cracking. A plain payload drop into a served or scheduled path goes to [[Shells]]. Read-only across everything closes this route: sweep the share as loot with [[Config-File-Looting]].

## Reading the output

Two things this note as a whole turns on.

The first is that SMB has **three different denials** and they demand three different moves. `NT_STATUS_ACCESS_DENIED` is a permission wall — the object exists, you may not have it, get a better credential. `NT_STATUS_LOGON_FAILURE` is a wrong credential — the account or password is bad, fix the pair. `NT_STATUS_BAD_NETWORK_NAME` is a wrong name — the share you asked for does not exist, stop blaming the credential. Reading the exact status before reacting is most of the skill on this port.

The second is that a read-only share is loot and a writable share is a foothold, and the line between them is one `put` test — never assume from the listing which one you are looking at.
